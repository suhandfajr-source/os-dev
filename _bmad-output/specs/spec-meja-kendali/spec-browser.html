SPEC.md — Meja Kendali

id: SPEC-meja-kendali · companions: release-plan.md, stage-scope.md, architecture-diagrams.md · sources: _bmad-output/forge/asisten-sdlc/forged-idea.md

Why

Vibecoder non-IT (pemilik aplikasi ini) sudah punya asisten AI percakapan (WhatsApp mode) tapi tidak punya tempat terstruktur untuk menjalani lifecycle SDLC — Planning sampai Maintenance — sesuai materi HaramainKU Sesi 2. Tanpa itu, proyek berjalan dari prompt ngasal: artefak tidak tersimpan, status tidak terlihat, dokumentasi hilang. Gabungan pain to solve dan opportunity: AI client, database, dan knowledge base sudah ada — yang kurang ruang kerja terstruktur per proyek.

Capabilities

CAP-1 — Dual mode. User beralih antara WhatsApp mode & Dashboard mode, satu backend sama. Success: pindah mode tanpa kehilangan state; data terbaca di kedua mode.
CAP-2 — Proyek entitas utama. Halaman depan Dashboard = daftar proyek; satu proyek = satu meja kendali. Success: proyek baru langsung punya meja kendali yang bisa dibuka.
CAP-3 — Wizard per tahap, AI di belakangnya. Form terstruktur: AI mendraf, user review/edit/approve. Success: wizard Planning mengubah brief jadi draf PRD yang bisa diedit & disetujui (bukan chat-driven).
CAP-4 — Status tahapan (Remind). Asisten menjelaskan status tiap tahap (selesai/belum) + apa yang belum dikerjakan. Success: tiap proyek menampilkan status 6 tahap + sisa pekerjaan konkret.
CAP-5 — Pencatatan artefak (Record). Artefak & keputusan yang disetujui tersimpan per proyek/tahap. Success: artefak approved tersimpan & bisa dibuka kembali.
CAP-6 — Paket handoff. Spec + acceptance criteria dari story siap tempel ke coding agent. Success: paket tergenerate dari story approved & siap disalin utuh.
CAP-7 — Akses tahap bebas. Tanpa kunci berurutan; disiplin lewat status advisory. Success: tahap mana pun bisa dibuka langsung, status tetap akurat.

Constraints

  • Mesin tidak pernah eksekusi — hanya draft/record/remind.
  • Urutan tahap di UI tetap Planning → Design → Development → Testing → Deployment → Maintenance, meski akses bebas.
  • Fitur WhatsApp mode existing (kamus FTS, simpan tools) wajib tetap berfungsi.
  • Stack existing: Next.js + SQLite/libSQL + Gemini client; tanpa infrastruktur baru di R1.
  • Model AI dua tingkat via env: AI_MODEL=gemini-3.6-flash (berat), AI_MODEL_LIGHT=gemini-3.5-flash-lite (ringan); fallback chain & retry existing dipertahankan.

Non-goals

  • Tidak ada monitoring realtime ala Sentry/PostHog dari dalam sistem.
  • Tidak ada eksekusi deploy/CI.
  • Tidak ada generate/kompilasi kode di dalam aplikasi.
  • Tidak ada multi-user/role system (personal tool).

Success Signal

User menjalankan satu proyek nyata end-to-end dari meja kendali: brief → spec/stories disetujui → paket handoff ditempel ke coding agent → hasil dicatat kembali — tanpa keluar dari Dashboard untuk artefak planning. TERUKUR

Assumptions

  • Personal tool single-user, tanpa auth/role system.
  • Skema data detail per artefak dirancang saat implementasi/architecture.
  • R1 fokus backend: Dashboard mengikuti pola UI existing; jalur bmad-ux ditunda, bukan dibatalkan.

Stage Scope — Peran Asisten per Tahap

Mesin = asisten, bukan eksekutor. Tiga kerja universal: Draft · Record · Remind. Eksekusi di meja kerja lain (user + coding agent + tool eksternal).
Tahap🔨 Draft📝 Record🔔 Remind
PlanningBrief tanya-jawab, draf PRD/spec, daftar pertanyaan belum dijawabKeputusan & alasannyaPertanyaan kritis belum terjawab
DesignDeskripsi wireframe, diagram mermaid, draf keputusan arsitekturKeputusan design & trade-offBagian design belum diputuskan
DevelopmentStory rapi, paket handoff untuk coding agentStatus story, changelog, keputusan teknis, bugStory belum selesai, dependensi
TestingTest plan & test case, acceptance criteriaHasil test manual, daftar bugTest belum jalan, bug belum tutup
DeploymentChecklist pre-deploy, config CI/CD, panduan deployLog deploy: tanggal, versi, rollbackChecklist belum dicentang
MaintenanceRencana monitoring, template retrospectiveCatatan insiden, hasil retro, pelajaranHal yang perlu dicek berkala

Pola: draft makin teknis ke kanan, record makin operasional ke kanan. Asisten tidak pernah mengeksekusi.
