- (decision) Sumber utama: _bmad-output/forge/asisten-sdlc/forged-idea.md (hasil sesi forge HARDENED); slug meja-kendali
- (decision) CAP-1 Dual mode: satu backend dua frontend (WhatsApp mode & Dashboard mode), user aktifkan salah satu, dapur (data/AI/KB) sama; success = pindah mode tanpa kehilangan state, keduanya baca-tulis data yang sama
- (decision) CAP-2 Proyek entitas utama: halaman depan Dashboard = daftar proyek, satu proyek = satu meja kendali berisi wizard tahapan; success = buat proyek baru lalu buka meja kendalinya
- (decision) CAP-3 Wizard per tahap dengan AI di belakangnya: form terstruktur, AI mendraf, user review/edit/approve; bukan chat-driven; success = wizard Planning mengubah input brief jadi draf PRD yang bisa diedit & disetujui
- (decision) CAP-4 Status tahapan (Remind): asisten menjelaskan status tiap tahap (selesai/belum) dan apa saja yang belum dikerjakan; success = tiap proyek menampilkan status 6 tahap + sisa pekerjaan konkret
- (decision) CAP-5 Pencatatan artefak (Record): artefak & keputusan yang disetujui tersimpan per proyek/tahap dan bisa dibuka kembali; success = artefak yang di-approve tersimpan dan tampil di meja kendali
- (decision) CAP-6 Paket handoff ke coding agent: dari story, user bisa hasilkan paket spec + kriteria selesai siap tempel ke coding agent; success = paket handoff berisi spec + AC tergenerate dari story yang disetujui
- (decision) CAP-7 Akses tahap bebas: semua tahap bisa dibuka kapan saja tanpa kunci berurutan; disiplin lewat status advisory (CAP-4); success = tahap mana pun bisa dibuka langsung dan statusnya tetap akurat
- (constraint) Mesin TIDAK pernah eksekusi: tidak ada deploy otomatis, integrasi monitoring realtime, atau eksekusi kode di dalam sistem — hanya draft/record/remind
- (constraint) Urutan tahap di UI tetap Planning→Design→Development→Testing→Deployment→Maintenance (materi HaramainKU S2) meski akses bebas
- (constraint) Fitur WhatsApp mode existing (kamus FTS, simpan tools) wajib tetap berfungsi — dashboard dibangun di sampingnya, bukan menggantikan
- (constraint) Bangun di stack existing: Next.js + SQLite/libSQL + Gemini client; tidak menambah infrastruktur baru di R1
- (constraint) Pemilihan model AI mengikuti bobot tugas: model murah untuk tugas ringan, model pintar untuk draf kompleks (prinsip materi Sesi 2)
- (decision) Non-goals: tidak ada monitoring realtime ala Sentry/PostHog, tidak ada eksekusi deploy/CI, tidak ada generate/kompilasi kode di dalam app, tidak ada multi-user/role (personal tool)
- (decision) Success signal: user menjalankan satu proyek nyata end-to-end dari meja kendali — brief → spec/stories disetujui → paket handoff tempel ke coding agent → hasil dicatat kembali — tanpa keluar dari Dashboard untuk artefak planning
- (assumption) Personal tool single-user tanpa auth/role system
- (assumption) Skema data detail per artefak (brief/PRD/story/log) dirancang saat implementasi/architecture, bukan di spec ini
- (question) Apakah Dashboard mode perlu melewati jalur bmad-ux (DESIGN.md/EXPERIENCE.md) sebelum R1 dibangun, atau wizard mengikuti pola UI yang sudah ada di aplikasi?
- (question) Model AI spesifik per bobot tugas wizard: pakai provider/model apa untuk draf kompleks vs ringan?
- (event) Self-validate Pass 1 (Coherence): LULUS — 7 CAP semua punya intent+success, intent WHAT bukan HOW, constraints membatasi desain, non-goals eksplisit, success signal teruji, ID stabil, prosa lean
- (event) Self-validate Pass 2 (Preservation): LULUS — semua klauul load-bearing dari forged-idea.md terpetakan ke SPEC.md atau companion (release-plan.md, stage-scope.md, architecture-diagrams.md); tidak ada drop material; wrapper-only content: tidak ada
- (decision) Open question UX terjawab: fokus backend dulu — Dashboard mode sementara mengikuti pola UI yang sudah ada di aplikasi; jalur bmad-ux (DESIGN.md/EXPERIENCE.md) ditunda, bukan dibatalkan
- (event) SPEC.md di-derive ulang: open question UX dipindah ke assumptions (R1 fokus backend, pola UI existing); tersisa 1 open question (model AI per bobot tugas)
- (decision) Open question model AI terjawab: dua tingkat via env di atas Gemini existing — AI_MODEL=gemini-3.6-flash untuk tugas berat (draf PRD, pecah stories, kritik), AI_MODEL_LIGHT=gemini-3.5-flash-lite (baru) untuk tugas ringan (ringkasan, checklist, status); fallback chain & retry existing dipertahankan per tingkat; tanpa provider baru
- (event) SPEC.md di-derive ulang: constraint model AI dikonkretkan (AI_MODEL=gemini-3.6-flash berat, AI_MODEL_LIGHT=gemini-3.5-flash-lite ringan); Open Questions kini kosong — semua terjawab
- (decision) Story Breakdown R1 disetujui user: 7 stories — 1 Fondasi Proyek (spec_checkpoint), 2 Mesin Status, 3 Model Dua Tingkat, 4 Wizard Brief→PRD (spec_checkpoint), 5 PRD→Spec+Stories, 6 Story Board+Changelog, 7 Paket Handoff (done_checkpoint); R2-R4 dipecah nanti setelah R1 selesai
- (event) stories.yaml ditulis: validasi schema LULUS — 7 entry, id quoted & unik & prefix-free ('1'..'7'), semua required fields terisi, tanpa status field, checkpoints sesuai persetujuan user, invoke_dev_with memuat catatan dispatch yang disepakati
