Meja Kendali — Asisten SDLC

Asisten Planning → Maintenance di dalam Personal Vibe Coding Assistant · hasil dari sesi "forge-idea"

Hasil

Idea lolos penempaan dalam kondisi HARDENED: setiap cabang utama tuntas mencapai keputusan konkret — bentuk produk, arsitektur dua frontend, filsafat asisten-bukan-eksekutor, struktur proyek, model interaksi wizard, kebijakan tahapan terbuka, dan empat gelombang rilis.

Keputusan yang Terkunci

  • Bentuk: fitur di aplikasi existing (Personal Vibe Coding Assistant), bukan produk terpisah.
  • Arsitektur: 1 backend, 2 frontend — WhatsApp mode (kamus & simpan tools) + Dashboard mode (meja kendali SDLC); dapur (data, AI, KB FTS) sama.
  • Filsafat: mesin = asisten, bukan eksekutor — Draft · Record · Remind. Eksekusi di meja kerja lain (user + coding agent).
  • Struktur: Proyek = entitas utama; halaman depan Dashboard = daftar proyek.
  • Interaksi: wizard/form terstruktur dengan AI di belakangnya; bukan chat-driven.
  • Tahapan: Planning → Design → Development → Testing → Deployment → Maintenance, bebas diakses; disiplin lewat status & sisa pekerjaan yang dijelaskan asisten.
  • Penghubung: paket handoff (spec + kriteria selesai) siap untuk coding agent.

Urutan Rilis

RilisIsiAlasan
R1Fondasi Proyek + mesin status + wizard Planning + fitur Development (story board, handoff, changelog)Development makan stories dari Planning — pisah = setengah jalan
R2Wizard Design + Testing + plan monitoringRingan, mandiri; plan monitoring tidak butuh riwayat
R3Maintenance penuh (insiden log, retrospective)Butuh riwayat dari tahap lain
R4Deployment (checklist, config generator, deploy log)Pelengkap

Ditolak & Alasannya

  • Monitoring realtime ala Sentry dari dalam sistem — bukan peran asisten; diganti rencana monitoring + catatan manual.
  • Tahap terkunci berurutan — ditolak user; disiplin dibuat advisory.
  • Chat-driven dashboard — diganti wizard terstruktur + AI di belakangnya.

Celah yang Bertahan dari Penempaan

  • Skema data detail per artefak (brief, PRD, story, log) belum didesain — pekerjaan tahap spec/arsitektur.
  • Bentuk visual Dashboard (komponen, layout wizard) belum digambar — ranah UX berikutnya.
  • Pemilihan model AI per bobot tugas wizard masih terbuka (prinsip sudah terkunci: murah untuk ringan).
