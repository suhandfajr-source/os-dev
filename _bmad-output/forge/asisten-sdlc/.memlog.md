- (decision) Opsi (A): fitur di aplikasi Personal Vibe Coding Assistant yang sudah ada — asisten memandu lifecycle Planning→Maintenance, dengan penyesuaian UI/UX; bukan produk terpisah, bukan sekadar workflow manual
- (decision) Dual mode UI: (1) WhatsApp native mode — rumah fitur kamus/knowledge-base dan simpan tools (existing); (2) Dashboard mode — rumah asisten SDLC dari Planning sampai Maintenance
- (decision) Dashboard mode = form/wizard terstruktur per tahap, AI bekerja di belakangnya sebagai generator/reviewer (bukan chat-driven); chat WhatsApp mode tetap untuk kamus & simpan tools
- (decision) Prioritas tahap: Planning duluan (fondasi), Maintenance wajib ada (kebutuhan nyata user), Deployment hanya pelengkap — bukan semua 5 tahap sekaligus
- (lock) REFRAMING PENTING: mesin ini ASISTEN, bukan EKSEKUTOR. Ia tidak membangun/men-deploy/memonitor — ia membantu manusia di SEMUA tahap: membuat brief, mencatat dokumentasi, dan tahu apa yang harus dikerjakan. Eksekusi tetap di luar sistem (manusia + coding agent + tool eksternal)
- (lock) Arsitektur: satu backend, dua frontend berbeda (tampilan WhatsApp & tampilan Dashboard) — dapur (data, AI, knowledge base) sama, tampilan & fitur terpisah; user mengaktifkan salah satu mode
- (lock) Dashboard = MEJA KENDALI: menyiapkan paket handoff (spec + kriteria selesai) untuk coding agent; proses development dieksekusi user di 'meja kerja lain' (di luar aplikasi, bareng coding agent). Konsep asisten-bukan-eksekutor dikonfirmasi benar
- (lock) Proyek = entitas utama Dashboard: halaman depan Dashboard = daftar proyek; satu proyek = satu meja kendali dengan wizard tahapannya
- (lock) Tahapan TIDAK terkunci, bebas diakses — disiplin tetap ada lewat asisten: mesin menjelaskan status tiap tahap (selesai/belum) dan apa saja yang harus dikerjakan. 'Disiplin dengan ruang fleksibilitas', bukan paksaan sistem
- (direction) Urutan rilis: wizard Planning dulu (fondasi), lalu Maintenance (kebutuhan nyata), Deployment sebagai pelengkap terakhir
- (lock) Urutan rilis final: R1 = fondasi Proyek + mesin status + wizard Planning + fitur Development (story board, handoff ke coding agent, changelog); R2 = wizard Design + Testing + plan monitoring (dari Maintenance, karena tidak butuh riwayat dan kebutuhan nyata user); R3 = Maintenance penuh (insiden log, retrospective); R4 = Deployment (pelengkap: checklist, config generator, deploy log)
