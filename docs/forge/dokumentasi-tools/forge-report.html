Ringkasan Hasil

Ide "dokumentasi tools" dipertajam lewat 4 cabang diskusi dan 6 keputusan terkunci: penyimpanan dengan konfirmasi (chips), entri 4 field, recall hemat via FTS lokal, UI tetap WhatsApp native, kelola lewat chat, dan satu knowledge base bertipe yang extensible. Fitur "Project Partner" ditunda sebagai produk terpisah berukuran project-sized.

Keputusan Terkunci

  1. Simpan setelah konfirmasi — chips Simpan 📦 / Edit / Skip, bukan auto-save
  2. Entri 4 field — nama, fungsi (bahasa awam), kapan dipakai, cara mulai. Ditolak: tags, link, tanggal+sumber
  3. Recall hemat — FTS lokal sebelum AI; suntik konteks bila cocok; tanpa cocok = nol biaya
  4. UI WhatsApp native — nol elemen baru di luar chat
  5. Kelola via chat — hapus selalu konfirmasi ulang
  6. Satu KB bertipe, extensible — tool/library/layanan/konsep (+ commit/bug/keputusan nanti)

Yang Ditolak & Mengapa

  • Auto-save semua tools → DB penuh sampah; butuh fitur kelola tambahan yang tak terhitung
  • Recall via LLM tiap pesan → 2× panggilan model per pesan, boros kuota Gemini
  • Recall pasif → KB jadi catatan yang tak pernah dibaca; fitur gagal diam-diam
  • Tab/halaman UI baru → melanggar prinsip WhatsApp native milik user
  • Eksekusi paralel dengan Project Partner → scope terlalu besar, dua-duanya berisiko gagal

Titik Lemah yang Selamat

  • KB tumbuh lambat bila user jarang konfirmasi simpan — pantau setelah rilis
  • Mesin bisa salah menyebut entri kurang relevan — ambang ketat + instruksi prompt
  • Ambiguitas perintah hapus — mitigasi: konfirmasi ulang wajib
